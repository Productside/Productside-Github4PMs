## Why GitHub.

GitHub is not a document manager. It is infrastructure for product context that is actively evolving, contested, and needs to be traceable.

&nbsp;

| What GitHub uniquely does | Why it matters for product teams |
|---|---|
| **Line-level diff** | See exactly what changed in a strategy document, a prompt, or a requirement, not just "edited by Dean, March 14" |
| **Branching** | Three people explore competing interpretations of new evidence without overwriting each other |
| **Commit messages** | The reasoning travels with the change, creating a trail of product logic, not just a timestamp |
| **Pull request review** | Propose a change, see the diff, discuss it, approve or reject before it becomes trusted context |
| **GitHub Actions** | Automate guardrails: block client names, check for credentials, validate structure on every PR |
| **AI harness integration** | Claude Code and Codex read the repo directly. The AI works from the team's actual context, not a pasted clipboard |
| **Fork and reuse** | Another team can adopt your playbook, adapt it, and contribute back improvements |

&nbsp;

**In plain English:** GitHub is where the thinking is still being argued. Everything else stores the result after the argument is over.
